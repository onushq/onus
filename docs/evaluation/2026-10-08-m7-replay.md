# Report accuracy on real pull requests (M7 replay, 2026-10-08)

Before the live field trial, Onus's reports on 20 large merged pull requests from two TypeScript monorepos were audited, the mistakes fixed, and the same pull requests audited again. Twenty (`twenty`, open-source CRM) supplied ten of them; the examples below come from it.

## Method

- **Reports**: `onus report --base <merge>^1 --head <merge>` for each pull request, with the release build. Nothing in the repositories was run.
- **Audit**: four reviewer agents, five pull requests each, with one brief. For every row they checked the claim against the code (`git show`, `git grep`) and graded it: the fact (correct, partly wrong, wrong), its value (important, useful, noise) and whether the ● or ○ flag was right. They listed misses (changes a reviewer must know about that no row reports) with a severity, and scored each report for usefulness and flag precision from 1 to 5. The second audit used the same brief on the new reports, by fresh reviewers.
- **Regression corpus**: every kind of mistake found became a small case with invented code in `crates/onus-cli/tests/corpus`, which runs with the test suite. Controls (a real breaking change, a really weakened test, a really removed `await`) keep the fixes from over-correcting.

## Results

| | Before | After |
|---|---|---|
| Rows audited | 133 | 154 |
| Rows with a wrong fact | 9 (7%) | 1 (under 1%), since fixed |
| Rows partly wrong | 21 (16%) | 11 (7%) |
| Usefulness, mean of 20 (1–5) | 2.1 | 3.0 |
| Flag precision, mean of 20 (1–5) | 2.05 | 3.5 |
| High-severity misses | 9 | 1 |

## What changed

The first audit found that the ● flags pointed the wrong way: most were false "breaking" alarms, while migrations, public endpoints and permission code sat in ○ "N changed lines inside X" rows. Examples from Twenty:

- **#27434** (removing unused module imports): four ● "contract changed" rows on a regenerated client SDK whose generator had started sorting its output. Types are now compared with object and union members sorted, and generated code is one quiet row; the four rows are gone.
- **#27482** (grouping charts by "Created by"): ● "tests weakened" for tests that moved word for word to a shared package with the function they test. Removed tests are now matched against the change's new tests, file by file.
- **#27421** and **#27428**: ● "tests weakened" for tests deleted together with the code they tested. They are now a quiet "tests removed with the code they tested" row.
- **#27430** (chat subscriptions): false "no longer awaits" and "no longer has an early exit" rows for a method whose body moved into a private helper, and "breaking" rows for new fields on GraphQL output types that nothing in the repository constructs. Awaits and guards that moved are no longer removals, and a contract change is breaking only when a user or implementation outside the change was not updated. The workspace upgrade command and the two new mutations, hidden before, now have ● rows.
- **#27420** (resolving how an object is shared): a permission refactor across the ORM was only "697 changed lines". Authentication and authorization code now gets its own ● row.

Across both repositories, the risk classes the first audit found unflagged are now ● rows: new and edited migrations (with the tables and columns they touch), GraphQL operations (separately when they skip authentication), HTTP routes, patched dependencies, root build config and infrastructure.

## What is still weak

- **The generic changed-lines row** still holds behavior that matters when nothing marks it: a shared helper whose behavior widens a public API (#27482), a refactor that moves a permission-scoped read into a resolver (#27440), a selection effect that changes what bulk actions target (#27426). Finding these needs facts about behavior across components, not file names.
- **Auth code is found by file names.** It flags dependency-injection wiring in `*.module.ts` files of auth modules (#27434, #27436), which reviewers called borderline, and misses a central access-decision function in a file without such a name (#27420).
- **Noise** remains in one-line internal rows, "inferred types changed" rows and config rows that repeat a dependency row.

These are inputs for the live trial, where reviewers' 👍/👎 and `/onus caught` replies will say which rows earn their place.
